# 开发、部署与验证

更新：2026-09-14。本文核对仓库脚本与代码，不表示本次已启动服务或重跑测试。架构见 [主文档](../项目架构与发布流程.md)，接续状态见 [接续工作](接续工作.md)。

## 1. 环境与工作目录

| 工作 | 需要什么 |
|---|---|
| 使用已发布前端 | Windows 和 `NT8Terminal.exe` / `dist`；无需 Node |
| 使用 NT8 桥 | 安装并配置 NinjaTrader 8，由其编译器加载 AddOn |
| 使用 ATAS 桥 | 已验证 ATAS X 8.0.14.646 / 8.0.15.643，桥目标 .NET 10 |
| 运行复制后台 | ASP.NET Core 10 Runtime；已有 .NET 10 SDK 也满足 |
| 构建前端 | Node / npm，依赖版本由 `app/package-lock.json` 固定 |
| 构建 ATAS 桥 | .NET 10 SDK 和完整本机 ATAS 程序集 |
| 构建复制后台 / 完整 ZIP | .NET 10 SDK；ZIP 还需 Node 与系统 .NET Framework csc |
| 浏览器回归 | Windows Edge、已构建 `app/dist`、测试脚本使用的隔离 profile / 端口 |

除明确进入 `app` 的命令外，下列命令在项目根目录、原生 PowerShell 执行。PowerShell 调 npm 使用 `npm.cmd` / `npx.cmd`，避免命中受策略限制的 `.ps1` shim。

## 2. 前端开发与构建

首次安装依赖和启动开发服务：

```powershell
Set-Location app
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 7100
```

需要手机访问时将 `--host` 改为主机局域网 IP 或 `0.0.0.0`。直接 `npm.cmd run dev` 使用 Vite 配置的 3000；7100 来自启动参数。`start.bat` 固定开放 `0.0.0.0:7100`，`start.sh` 固定本机 7100，`prod` 参数使用 Vite preview，不等同正式 EXE 服务。

前端生产构建（根目录）：

```powershell
.\app\build.cmd
```

输出 `app/dist`。正式静态服务读取它，开发服务读取源文件。构建不应全局结束 esbuild，也不能删除运行中开发服务的 `app/node_modules/.vite`；生产构建已用 `.vite-build` 隔离缓存。单独修改文档无需构建。

按改动文件运行 ESLint，例如：

```powershell
Set-Location app
npx.cmd eslint src/sections/ChartTerminal.tsx src/hooks/useOrderLines.ts
```

仓库保留的独立 `<script>` 提示和大 chunk 警告需要与真正构建失败区分，不能因看到警告就声称构建失败。

## 3. 绘图库资源

运行资源在 `app/public/charting_library/`，完整来源为本地 `charting_library_v32.1/`。先校验再同步，最后构建：

```powershell
node scripts/sync-charting-library.mjs --check
node scripts/sync-charting-library.mjs
.\app\build.cmd
```

可用 `--source <目录>` 指定来源。校验器当前要求 `CL v32.1.0`，核对入口、中英文资源及 runtime 引用的懒加载 JS / CSS；升级其他大版本需同时检查校验器和适配代码。GitHub 网页的 1000 文件预览不代表目录完整，不能用不完整 bundles 覆盖运行副本。

同步前验证，旧 public 备份到 `.tmp-webbridge/charting-library-sync-*/previous`。当前 `app/index.html` 使用版本查询参数 `32.1.0`。不要混用 v29 / v32 bundles，不直接修改 vendor 来修业务问题。

## 4. NT8 桥

源文件为 `nt8-bridge/TvBridgeAddOn.cs`。安装副本在 NT8 用户文档目录的 `bin/Custom/AddOns/TvBridgeAddOn.cs`；实际用户目录可能因系统配置变化，不硬编码用户名。

更新流程：备份已有安装副本 → 复制新 `.cs` → NT8 的 NinjaScript Editor 按 F5 编译 → 检查本机 `/api/status` 能力值。如果仍加载旧实例，再安排重启 / 重新加载；仅刷新网页不能升级 AddOn。

只读状态：

```powershell
Invoke-RestMethod http://127.0.0.1:8090/api/status
```

当前源码应包含 `historyWindowVersion=1`、`executionArchiveVersion=1`、`symbolCatalogVersion=2`、`copySnapshotVersion=1`。安装、接口及排障见 [NT8 README](../nt8-bridge/README.md)。

原生编译验证（需要本机 NT8 程序集；脚本包含本机路径，换机器先核对）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-symbol-catalog.ps1 -CompileNative
```

## 5. ATAS 桥

构建并运行模拟平台测试：

```powershell
.\atas-bridge\build.cmd -AtasPath "D:\Program Files\ATAS X" -Test
```

将路径替换为实际安装目录。输出 `atas-bridge/dist/TvAtasBridge.dll`，中间产物在 `.build-check/atas-bridge`。加载时在 ATAS 使用 **Add custom indicator**，再向一个图表添加 **TradingView Terminal Bridge** 并保留该图表。常见加载目录为 `%APPDATA%\ATAS X\Indicators\`，以本机 ATAS 设置为准。

```powershell
Invoke-RestMethod http://127.0.0.1:8091/api/status
```

当前桥版本 5、显示关联能力 1，`version` 是实际平台版本。初始化错误看 `error` / `bridge-errors.log`，行情看 `marketError`，交易看 `tradingError`，归档看 `archive`；不能将普通拒单一概当作长期保护异常。版本 5 修复网页 SSE 连接断开被记为行情故障；market 测试覆盖数据帧 / 心跳的写入和刷新断连、正常帧格式及取消。

DLL 热替换有旧桥排空和新桥接管机制，但编译文件存在不等于已经加载；应核对状态版本。不要随意复制 ATAS 自带程序集。最后一个桥接指标移除后服务停止，已提交工作单不因此撤销，保护生成 / 数量同步也停止。细节见 [ATAS README](../atas-bridge/README.md)。

## 6. 复制后台

```powershell
.\copy-trading\build.cmd -Test
.\copy-trading\start.cmd
```

第一条构建 / 测试，不启动实盘跟随；第二条在后台隐藏启动服务。发现 8092 已被监听会保留现有进程，不自动替换它。Vite 不负责启动复制服务，正式 EXE 则会在产物存在且端口空闲时启动。

```powershell
Invoke-RestMethod http://127.0.0.1:8092/api/status
```

上面是只读检查。规则保存后默认停用；启用会影响实际账户，不能作为构建验证步骤。重启复制服务会暂停原运行规则，不自动恢复。关闭浏览器或网页服务不会停止已启用规则；停用不平仓，已发出的请求仍可能成交。

默认数据在 `%LOCALAPPDATA%\NT8Terminal\CopyTrading`，不在程序产物目录。独立测试可用 `--port` / `--data-dir`，但程序还有会话级 mutex，不能认为换端口就允许第二个真实执行器。操作范围见 [复制服务 README](../copy-trading/README.md)。

## 7. 静态托管与打包

单独编译静态服务（根目录）：

```powershell
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /target:exe /platform:anycpu /out:NT8Terminal.exe server\StaticServer.cs
.\NT8Terminal.exe 7200
```

没有 Framework64 时可使用 `Framework\v4.0.30319\csc.exe`。EXE 优先读取旁边的 `app/dist`，否则读取 `dist`；支持 `--host <IP>`、`--no-browser`。程序会尝试启动旁边的复制后台，因此只检查静态代码时使用隔离代理测试，而不是为了编译验证随意启动服务。

完整打包：

```powershell
.\pack.bat
```

当前 ZIP 内容：

```text
NT8Terminal.exe
README.txt
TvBridgeAddOn.cs
dist/                       前端，包括运行绘图库
copy-trading/               CopyTrading.exe、依赖、runtimeconfig、启动脚本和 README
```

`server/package.ps1` 在 `.build-check` 隔离暂存后压缩。**ATAS DLL 不在当前包内**；需要 ATAS 时另建并交付 `atas-bridge/dist/TvAtasBridge.dll`。完整 ZIP 包含非自包含 .NET 10 复制程序，所以目标机器还需要 ASP.NET Core 10 Runtime，不再是旧文档的“只有 Windows + NT8 即可”。

更新按层部署：前端换 `dist`；代理变更换 EXE 并重启网页服务；NT8 / ATAS 按各自平台加载；复制后台需确认旧进程和规则状态后更新。程序产物不能覆盖成交归档、保护计划或复制 `state.json`。

## 9. 故障定位

| 症状 | 优先检查 |
|---|---|
| 手机 / 远程显示桥未连接 | 用远程网页同源 `/api/status`、`/atas/api/status`；再在平台主机查回环 8090 / 8091，区别代理失败与平台未加载 |
| ATAS 服务异常 | 实际 `version` 是否被支持、指标是否挂载、`error` 与初始化日志；不要只改白名单 |
| ATAS 有持仓无仓位线 | 账户来源、完整 chart symbol、positions 的 `instrument/chartSymbols`、均价；连续 / 月份及大小写是否按显式关联匹配 |
| 切合约后线消失 / 旧线残留 | `useOrderLines` scope、generation、`getAllShapes` 与隐藏旧 ID，布局 `dataReady` 恢复 |
| 隐藏账户再次出现 | localStorage 是否被清除 / origin 是否改变；确认没有重新引入按账户快照清理偏好 |
| 布局刷新丢失 | `save_load_adapter`、origin、存储异常、layout scope；保留旧数据检查，不能清空后假报修复 |
| 交易详情黑屏 / 504 | 懒加载错误边界与 Vite 预打包缓存；不删正在使用的 `.vite` |
| 历史断续 | 比较原生图表、窄窗与宽窗结果、from/to 时区、交易时段和能力版本；不要补平盘假 bar |
| 复制服务未启动 | 8092、ASP.NET Core 10 Runtime、产物路径；Vite 不会代为启动 |
| 复制规则暂停 | 读状态 error / 日志、真实账户快照、Pending、归档；不靠反复启用或重发消除不确定订单 |
| 构建停在 transforming | 原生 PowerShell / cmd、单次构建进程；保留运行中的开发服务和缓存 |

只读历史诊断会访问**实际 NT8 桥**，区别于模拟测试：

```powershell
node scripts/diagnose-history.mjs "NQ SEP26" "2026-09-04T08:00:00Z"
```

这是历史复现样本，不是当前主力建议。按待诊断原生合约和时间替换；结果写 `.tmp-webbridge/history-diagnosis.json`。浏览器可查看 `__dfLog`、`__olLog`、`__rpLog`、`__layoutLog`；`__lastWidget` / `__tvDatafeed` 是调试入口。不要把调试交易方法当成只读检查。

正式 `StaticServer.ProxyApi` 重建本机请求，仅显式转发 Content-Type、Accept、Last-Event-ID、Authorization 及请求体；Vite 使用另一套代理实现。排查设备信息 / IP 传递时需区分这两种模式和外层代理，不应仅凭“桥是回环”推断所有 HTTP 头都相同。
