# 复制交易后台服务

运行需要 Windows 和 ASP.NET Core 10 运行时（安装 .NET 10 SDK 也可）；从源码构建需要 .NET 10 SDK。服务仅监听本机 `127.0.0.1:8092`，网页通过同源 `/copy/api/*` 访问，远程设备无需连接此端口。

使用 HTTPS 反向代理时，也要转发 `/copy/api/*` 并保留原始 `Host`（含非默认端口）。前端服务器会验证复制请求的来源与该地址相同，再转发到本机服务。

开发时先执行 `copy-trading\build.cmd`，再执行 `copy-trading\start.cmd`。启动脚本在后台隐藏运行服务，发现端口已有监听时保留现有进程。前端 Vite 开发服务器不会自动启动该服务。

打包发布后，`NT8Terminal.exe` 会在 `copy-trading\CopyTrading.exe` 存在且端口空闲时自动启动服务。首次运行没有启用的复制配置，需要在网页中配置并启用。关闭浏览器或前端服务器不结束后台服务；停止跟单请先在网页停用配置。需要退出后台时，可在任务管理器结束 `CopyTrading.exe`。

规则和执行状态保存在 `%LOCALAPPDATA%\NT8Terminal\CopyTrading\state.json`，更新程序不会覆盖该目录。服务重启后，原本运行的规则会暂停，需要重新在网页启用。

`build.cmd -Test` 同时构建并运行 `tests` 目录下的控制台回归测试。构建临时产物在仓库 `.build-check\copy-trading`，发布文件在 `copy-trading\dist`，两者均不进入 Git。

网页进入“复制交易”，新建规则并选择主账户、跟随账户和数量倍率。同桥可沿用原合约名称；跨 NT8 / ATAS 须填写两边完整原生合约映射。保存后仍为停用状态，手动启用前所有参与账户须空仓且没有工作订单。NT8 需要使用支持 `copySnapshotVersion=1` 的新 AddOn，旧桥会提示更新编译。

当前采用成交跟随：主账户实际成交后，目标账户提交市价单；主账户止盈止损成交时跟随退出，不提前复制未成交挂单。倍率作用于净持仓，向零取整后下差量；“最大单笔手数”限制每一次实际复制请求。断线、手动改变目标持仓、缺少映射、存储或下单异常会暂停；不自动重发未确认订单。停用跟随不会平仓，已发送的订单仍可能成交。
